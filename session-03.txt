Point-1) External Source:- Where does content originate?
  - What is this External Source? 
    Sources of software packages, container images, configuration contents and security compliance conetnets.
	
  - Why use them ? 
    Satellite needs trusted software and management contents to distribute to servers.
	
  - Example:- Obtain RHEL security updates from Red Hat and an internal monitoring packages from "Dell's repository"
  

- Red Hat Content Delivery Network (CDN):-
  - Red Hat Software repositories.
  - Example:- RHEL packages and security fixes.

- Puppet:- 
  - Configuration Management Content.  
  - Example:- Define a standard service configuration.
  
- Docker:-
  - Container images contents.
  - Example:- An application container images.
  
- Git:-
  - Version-controlled contents.
  - Example:- Configuration or automation files.
  
- SCAP (Security Content Automation Protocol):-
  - Organization-specific software 
  - Example:- Dell monitoring agent RPM.

Note:- These lables represnt different conetnet types, their integration methods and availability depends on Satellite version and configuration.

 Satellite Server - Where is everything controlled?
  - What ? Central management system containing the components as part of architecture figure.
  - Why use it? -> Admins need one place to manage hosts, repositories, subscriptions and approved software version.

Point-3) 
Pulp:- Synchonize and store the actual content.
  What is pulp -> Repository and content service used by Satellite.
  Why to use?  -> To download conetnet, store it locally and support distribution to Capsules.
  
  Eaxmple:- Pulp Synchonize RHEL repositories containing packages such as httpd and their update.
  
Point-4) Candlepin -> manage subscriptions information.
  - Satellite's subscription management service.
  - Example:- Dell import a Red Hat subscription manifest and Candlepin hanlde it's subscription information.
  

Point-5) Katello - Control software lifecycle.
  - What is Katello -> Foreman plug-in that integrate repositories, contents lifecycle and subscription management.
  - Why to use ? -> To contorl which conetnet version different host can access.
  - Example:- Publish a conetnet view version which containing selected RHEL conetnet, and test it in Development environment (non-prod env) and then promote the same version though Testing to Production (Prod environment).

         Example:- Provision 10 Delhi application server using standard RHEL kickstart template.

   What is this ? -> Capsules functionality included within the Central Satellite server.
